# NewsFlow — бизнес-сущности на Go

Домашнее задание по backend-разработке на Go. Проект описывает предметную область NewsFlow — помощника редакции в Telegram: сбор новостей, оценку источников, проверку утверждений, рекомендации и подготовку публикаций.

## Состав

Все модели находятся в пакете `domain`. Для основных сущностей определены структуры, для статусов и категорий — отдельные строковые типы и константы. Используются только стандартные типы и пакет `time`, внешние зависимости не нужны.

| Файл | Сущности и назначение |
| --- | --- |
| `common.go` | ID, Tag, Attachment, Evidence — общие типы и вложенные значения |
| `source.go` | Source — внешний источник; TrustRating — его оценка доверия |
| `news.go` | NewsItem — исходная публикация; Event — общий инфоповод |
| `fact_check.go` | Claim — проверяемое утверждение; FactCheck — результат проверки |
| `editorial.go` | Editor — редактор; Channel — канал редакции; ChannelProfile — интересы канала |
| `submission.go` | Submission — сообщение из читательской предложки |
| `publication.go` | PublicationDraft — черновик для выбранной площадки и формата |
| `recommendation.go` | Recommendation — рекомендация; RecommendationFeedback — реакция редактора |

## Связи между сущностями

### Значения типов и полей

- `ID` — строковый идентификатор сущности; способ его генерации выбирается при реализации приложения. `Tag` — тематический тег, например «экономика» или «спорт».
- `Attachment` — фотография, видео или другой приложенный материал: `URL` хранит адрес, `MIMEType` — тип содержимого, `Caption` — подпись.
- `Evidence` — материал, подтверждающий или опровергающий утверждение. `OriginalURL` указывает первоисточник и помогает отличать независимые подтверждения от перепечаток.
- `Source` поставляет информацию, а `Channel` — редакционный канал, для которого готовятся и публикуются материалы. `Source.Enabled` позволяет приостановить сбор, сохранив историю источника.
- `TrustRating` хранит текущую оценку доверия источнику. Популярность источника сама по себе не показывает его надёжность.
- `Editor` — администратор, который выбирает новости и принимает окончательное решение о публикации. `ChannelProfile` хранит интересы редакции и предпочтения по оформлению: темы, регионы, тон и форматы.
- `NewsItem.OriginalURL` — ссылка на предполагаемый первоисточник, если он найден. Пустой `NewsItem.EventID` означает, что публикация ещё не отнесена к инфоповоду.
- `Event.Summary` — краткое описание инфоповода, а не готовый текст для публикации.
- `Claim` — отдельное проверяемое утверждение. `FactCheck` хранит результат одной его проверки; противоречия не равнозначны доказанному опровержению всей новости. `FactCheck.CompletedAt` равен `nil`, пока проверка не завершена.
- `Submission` — сообщение из читательской предложки конкретного канала. Его утверждения проверяются через `Claim` и `FactCheck`.
- `PublicationDraft` — редактируемый материал на основе одного инфоповода. Генерация текста не разрешает автоматическую публикацию: перед отправкой редактор должен утвердить материал.
- `Recommendation.Score` — относительная полезность инфоповода для конкретного канала, а не вероятность истинности новости. `Reasons` объясняет редактору причины рекомендации. `RecommendationFeedback` хранит реакцию редактора для улучшения рекомендаций.

### Ссылки и история

- Один Source поставляет множество NewsItem.
- Event объединяет несколько NewsItem и Submission об одном событии.
- Claim принадлежит одной NewsItem либо одной Submission. У Claim может быть несколько FactCheck: это история повторных проверок.
- FactCheck содержит подтверждающие и противоречащие Evidence; ссылка на первоисточник помогает выявлять перепечатки.
- Channel объединяет редакторов через EditorIDs и содержит профиль интересов ChannelProfile.
- Submission направляется в один Channel и может быть рассмотрена одним Editor.
- Recommendation связывает Event с Channel. RecommendationFeedback связывает рекомендацию с реакцией Editor.
- PublicationDraft связывает Event и Channel, хранит автора, формат, площадку, ссылки и данные об утверждении и публикации.

Связи заданы через ID, а не через вложенные копии сущностей. Это позволяет позднее сохранять модели в базе данных и не дублировать изменяемые данные.

## Правила предметной области

1. Оценка доверия источнику и оценка полезности рекомендации — разные показатели. Обе используют диапазон 0–100; конкретные алгоритмы пока не реализованы.
2. Источник без оценки отличается от источника с нулевым доверием благодаря полю Evaluated.
3. Несколько перепечаток одного сообщения не являются независимыми подтверждениями.
4. Для нового FactCheck используется CheckPending; для завершённого — CheckConfirmed, CheckContradicted или CheckInsufficient. Отсутствие данных не подтверждает утверждение.
5. У Claim заполняется ровно одно из полей NewsItemID и SubmissionID.
6. Принятие сообщения из предложки в работу не подтверждает его достоверность.
7. Черновик проходит статусы DraftEditing → DraftApproved → DraftPublished. Редактор также может отклонить черновик через DraftRejected. При изменении утверждённого текста потребуется повторное утверждение.
8. Для утверждённого черновика заполняются ApprovedBy и ApprovedAt, для опубликованного — также PublishedAt и PublishedURL.

Правила описаны как требования к будущей реализации. Структуры сами не проверяют значения: в рамках этого задания представлены модели, а не готовая бизнес-логика. При создании моделей нужно явно задавать статусы, поскольку нулевое значение строкового типа — пустая строка. Неизвестные даты обозначаются nil; необязательные ссылки на сущности — пустым ID.

## Проверка

Нужен Go версии 1.22 или новее. Из каталога с go.mod:

```sh
go build ./...
go vet ./...
```

Это библиотечный пакет, поэтому точки входа main и команды запуска сервера нет. HTTP-обработчики, база данных, парсер, Telegram-бот и вызовы ИИ в домашнее задание не входят. Структуры не привязаны к JSON или таблицам: форматы обмена и хранения можно добавить при реализации соответствующих слоёв.
